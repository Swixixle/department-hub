# Version 16

Ask now plans and executes supported ranking, comparison and per-person count questions. The plan carries the metric, shift, role, date range, people, exclusions and ties; the visible understanding line describes those fields. Vocabulary and conversation repairs cover ordinary work phrases, date/shift corrections and a follow-up about the hours of the shift already shown. This is still a bounded, LLM-free interpreter, not general English understanding.

The English-library experiment remains an experiment. Compromise was not added to application dependencies. Reported container import/parse timings are not phone measurements, and a library's compressed size should be compared with the same compression of an application entry bundle. A future library must demonstrate useful parsing gains on fresh language; tagging alone does not create a department query plan or solve nested clauses.

## Review corrections

The shared server now validates the whole exchange against the existing trade engine, rechecks every participant's membership and maintains receipts with explicit per-department sequence numbers. Regression tests cover new overlapping/rest-conflicting assignments, stale participant state, started shifts, timestamp ties and clock changes. Unrelated people's trades do not invalidate an otherwise unchanged proposal.

Integration review added eight regressions that failed against the supplied candidate: seven app cases and one real-HTTP case. Fixes apply custodian restrictions to computed per-person counts, retain explicit weekdays, separate numeric ranking limits from dates, include both shifts when requested, restrict rankings to a named group, select the lower value for “fewer,” and clear an old ranking plan after a new topic. The computed-count boundary is also checked through the production form and shared contract. These cases are now regression tests, not an untouched accuracy sample.

The two developer-written evaluation sets remain in use as regressions. Their original reported scores were 49/63 and 42/48, with two confidently wrong answers in each. Both sets have since been tuned against. Passing them is not a measurement of new coworkers' language.

## What is and is not connected

The repository contains a persistent local server, synthetic seeder, real-HTTP permission gate, server passkey verification/recovery operations and a tested shared-board adapter. The application still selects its local browser adapter. No sign-in screen, shared schedule/feed UI or production service has been enabled by this release. There has been no physical-phone passkey test or two-person confirmation exercise. Production domain/RP configuration and multi-process deployment validation remain outstanding.

Sign-in means no email typed at sign-in and no Department Hub password. Email's other purpose remains open; contact email, administrator-only recovery email and two distinct fields are alternatives. App-sent email/SMS and a new patient-information detector were not built. The existing Share handoff remains unchanged. No imported private workspace, real contact directory or private testing corpus is included in these commits.

The release changes source and the fictional demo after the usual verified publication. It does not update a previously installed standalone folder or its browser data automatically. Existing local receipts and checkpoints retain their original bytes and build identities.
